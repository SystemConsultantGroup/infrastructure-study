# MAC / IP / TCP

[전체 커리큘럼으로 돌아가기](../../README.md)

## 기본 정보

- **대상:** 애플리케이션 개발자
- **담당 인원:** 2명
- **시간:** 120분

## 학습 목표

호스트 사이의 통신을 링크, 네트워크, 전송 계층의 책임으로 나누어 이해합니다. 참가자가 연결 실패를 만났을 때 어느 계층부터 확인할지 가설을 세울 수 있는 것이 목표입니다.

컨테이너나 Kubernetes를 전제로 하지 않고, 일반적인 네트워크의 기본 원리에 집중합니다.

## 준비 방향

프로토콜 정의를 순서대로 나열하기보다, 준비팀이 고른 통신 사례를 통해 개념을 연결합니다. 같은 네트워크 안의 통신, 라우터를 지나는 통신, TCP 연결 가운데 일부를 선택하거나 하나의 이야기로 묶어도 좋습니다.

도구는 개념을 확인하기 위한 수단입니다. 실습을 포함한다면 `ip`와 `ping`을 기본으로 하고, 다른 도구는 필요에 따라 선택합니다.

아래 질문은 탐구 방향을 제안할 뿐, 발표 순서나 필수 질문을 뜻하지 않습니다.

## 탐구 주제

### 계층과 주소

- 통신을 여러 계층으로 나누면 어떤 책임을 분리할 수 있는가?
- MAC 주소와 IP 주소는 각각 어디에서 의미가 있는가?
- 계층 모델과 실제 구현이 깔끔하게 일치하지 않는 경우는 무엇인가?

### 이웃과 라우팅

- 송신자는 목적지가 가까이 있는지 라우터를 거쳐야 하는지 어떻게 판단하는가?
- 인터페이스, `prefix`, `neighbour`, `route`, `gateway`는 어떻게 연결되는가?
- 홉을 지날 때 바뀌는 정보와 종단 간 유지되는 정보는 무엇인가?
- 한 호스트가 전체 경로에 대해 알 수 있는 범위에는 어떤 한계가 있는가?

### ICMP와 관찰의 한계

- ICMP는 IP 통신에서 어떤 역할을 맡는가?
- `ping`의 성공이나 실패로 무엇을 알 수 있고, 무엇은 알 수 없는가?
- 네트워크 연결성과 애플리케이션의 정상 동작은 왜 같은 의미가 아닌가?

### TCP의 개념 모델

- TCP는 애플리케이션에 어떤 추상화를 제공하는가?
- 연결의 시작, 데이터 전달, 종료 과정에는 어떤 상태가 필요한가?
- 순서 보장, 재전송, 흐름 제어는 어떤 문제를 해결하는가?
- 애플리케이션 개발자는 timeout, connection refused, reset을 어떻게 구분해야 하는가?

### 선택 탐구

준비팀은 주제를 더 잘 설명하는 경우에 한해 `mtr`, `hping3`, `iperf3`, `ss`, `nc` 등을 활용할 수 있습니다. 도구의 사용법보다 어떤 가설을 검증할 수 있는지와 결과의 한계를 함께 다룹니다.

## 범위

### 핵심 범위

- 계층화와 책임 경계
- MAC 주소와 IP 주소의 관계
- 이웃 탐색과 라우팅의 기본 개념
- ICMP의 역할
- 애플리케이션 관점의 TCP 연결
- 관찰 결과로부터 가설을 검토하는 방법

### 범위 밖

- 컨테이너와 Kubernetes 네트워킹
- 커널 내부 패킷 경로
- 패킷 헤더 암기
- 혼잡 제어 알고리즘의 세부 비교
- 패킷 캡처를 이용한 심층 분석
